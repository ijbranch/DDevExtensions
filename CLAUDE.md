# DDevExtensions - Claude instructions

Our fork of Andreas Hausladen's DDevExtensions ( GitHub `ijbranch/DDevExtensions` ), an IDE expert DLL.  Global `CLAUDE.md` and the GITLAK standards apply.  Read `README.md` and `Help.md` before work.

- **In service as soon as built** ( Ian, 2026-10-29: "There is no [UnReleased].  As soon as they are generated they go into service." ): `CHANGELOG.md` and `DDevExtUnitTests/CHANGELOG.md` open with `## [In-Service]`, as GITLAKLib, GITLAKDB and the `gll*` forks do.
- **Versions** are `major.feature.fix` ( README "Version Number Interpretation" ): a bug fix moves the third digit.  A bump changes `Code/DDevExtensions/version.bat`, `version.h`, `Source/version.inc`, every `D_D1xx/DDevExtensions.dproj`, `Installer/DDevExtensionsReg.dproj`, and `Version.res` recompiled from `Version.rc` with `brcc32` ( `cgrc` fails here: no `rc.exe` ).
- **Delphi 13 builds** come from `Code/DDevExtensions/D_D130/DDevExtensions.dproj` ( group `D_D130/DDevExtensions.groupproj` ): Win32 gives `Bin/DDevExtensionsD130.dll` for the 32-bit IDE ( `bin\bds.exe`, registry `Experts` ), Win64 gives `Bin/DDevExtensionsD130x64.dll` for the 64-bit IDE ( `Experts x64` ).  Build both; a clean Win64 build deletes the Win32 DLL, so build Win32 after it.  `verify_change` builds only Win64.
- **Parallel Build All** ( `Source/ParallelBuild`, 3.25.16 ): the Project Manager's right-click Build All on a group node does NOT run the `ProjectBuildAllCommand` action, so it is replaced through `IOTAProjectMenuItemCreatorNotifier` ( item found by `Position = pmmpBuildAll` ).  The IDE passes `IsMultiSelect` True for a single selected group node: never test it there ( found by logging on 2026-11-10 after two wrong guesses; log what `AddMenu` receives before theorising ).  The EurekaLog rules in `ParallelBuildCore` are a deliberate RTL-only port of GITLAKMCP's `build_project`: change both together.
- **Older project files** ( `D_D102` to `D_D120` ): they cannot be built here ( only Delphi 13 is installed ), so a new unit goes into each `.dpr` AND each `.dproj` by hand.  The 2026-11-10 sync copied each missing `DCCReference` block from `D_D130/DDevExtensions.dproj`, after the last `.pas` reference; check with a count of `.dpr` units against `.dproj` references.
- **Deploying** to `%APPDATA%\DDevExtensions`, with every IDE closed: copy the installed DLLs to `C:\ProgramData\GITLAK\DDevExt-predeploy-<date>\` first ( with a README saying how to undo ), then copy both new DLLs over, and check their hashes match `Bin`.
- **The 32-bit IDE** loads its own experts and packages: test start-up and close there as well as in the 64-bit IDE, and dump before clicking OK on any IDE fault dialog ( x86 `cdb.exe` for the 32-bit IDE ).  On 2026-10-29 its start-up and close faults were not DDevExtensions: they needed LMD's packages and our gllStaticCodeAnalyser IDE expert loaded together, and stopped with the analyser disabled ( DDevExtensions' Keybindings only triggered the start-up one ).  `DDevExtensions.DisabledFeatures` ( environment, `;`-separated feature names such as `Keybindings`, read in `RegisterPlugins.pas` and parsed by `FeatureSwitches.pas` ) switches features off for a test; a name that matches no feature of any DDevExtensions version is logged and shown once per distinct set ( marker `%APPDATA%\DDevExtensions\DisabledFeatures.warned` ).
- **Older IDE projects:** `D_D102` ( Delphi 10.2 ) can no longer compile the shared code, which uses inline variables ( Delphi 10.3+ ); `D_D103` to `D_D120` cannot be built on this machine and are untested.
  - The DUnitX suite's `DDevExtUnitTests/DDevExtUnitTestsDUnitX.dproj` defines `EUREKALOG` for Win32 and Win64, so building the suite needs EurekaLog installed: the `.dpr`'s `{$IFDEF EurekaLog}` block names EurekaLog's own units ( `EMemLeaks`, `EBase`, ... ), and only `EExtraExceptionInfo.pas` is copied into the suite.
